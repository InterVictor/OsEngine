# Серверная (headless) сборка OsEngine — этап 0, разведка

Дата: 2026-09-21. Релиз OsEngine 2.0.1.8. Инструменты: `headless/`.

## Цель

Выделить из OsEngine исполняемую часть «Роботы Light» для запуска на Ubuntu без графики. Отладка роботов, тестер,
оптимизатор, загрузка данных остаются в обычном OsEngine на ПК. Управление сервером — через MCP API по SSH-туннелю.

## Метод

`headless/OsEngine.Headless` — проект `net10.0` (без `-windows`, без WPF/WinForms), который берёт исходники ядра
ссылками из `D:\OsEngine-masterBB\project\OsEngine` (путь меняется свойством `OsEngineSrc`), ничего не копируя.

- `seed.txt` — стартовый набор: Entity, Candles, Indicators, Journal, Logging, Language, Attributes, PrimeSettings,
  BotPanel, BotTabSimple, BotTabScreener, OsTraderMaster, ServerMaster/AServer, коннектор Binance Futures, MCP API
  (без модулей тестера, оптимизатора и OsData).
- `closure.sh` — транзитивное замыкание: собирает проект, по ошибкам «тип не найден» добавляет файлы ядра из `index.tsv`
  (индекс «тип → файл»), пока добавлять нечего. Окна (`*.xaml.cs`) не добавляются никогда.
- `build.sh` — сборка, ошибки в `errors.txt`, недостающие типы в `missing.txt`.
- `Stubs.*.cs` — пустые заглушки, только для подсчёта (не рабочие): типы WPF/WinForms/Chart, окна OsEngine,
  классы и пространства имён ненужных коннекторов.

Прочее:
- Коннектор Binance Futures от интерфейса почти не зависит (использует сущности из Binance Spot — добавлены).
- `SystemAnalyzeMaster` использует `PerformanceCounter` (только Windows) — пакет подключается, но на Linux не работает.
- Компиляция скриптов роботов (`BotFactory`, Roslyn) берёт ссылки из загруженных сборок, а не из фиксированного списка —
  на сервере роботы будут компилироваться против серверной сборки.
- Пути: ~450 строк вида `"Engine\" + name` / `@"Custom\Robots"`. На Linux `\` — обычный символ имени файла,
  не разделитель. Работоспособность надо проверить в рантайме (этап 1).

## Два пути для этапа 1

**А. «Хирургия»**: правки `#if HEADLESS` в ~15 смешанных файлах ядра (~1300 строк, в основном целые методы отрисовки),
замена ~15 графических файлов облегчёнными версиями, исключение ненужных вкладок и коннекторов из фабрик.
Минус — большой патч, его придётся переносить при каждом обновлении OsEngine.

**Б. «Фальшивый интерфейс» (рекомендуется)**: ядро не трогаем (или почти), в серверный проект добавляем библиотеку-имитацию
использованной части WPF/WinForms/Chart (~200 типов, ~500–1000 членов), где всё — пустые операции; `MainWindow.GetDispatcher`
выполняет действие сразу. Правки ядра — только фабрика коннекторов/вкладок (или заглушки-наследники). После обновления OsEngine
компилятор сам покажет, чего не хватает в имитации. Роботы (FF142/FF143 с отладочным графиком спектра) компилируются без изменений.
Риск — графический код, который реально выполняется на сервере (например, создание таблиц в конструкторах): имитация должна быть
безопасной (возвращать пустые коллекции, а не null); ловится запуском в WSL/эмуляторе.

## Следующие шаги

1. Установить WSL (Ubuntu) на ПК — рантайм-проверки без аренды сервера.
2. Имитация интерфейса по пути Б, итеративно до нуля ошибок сборки.
3. Точка входа без окон: запуск OsTraderMaster в режиме Light, MCP API, логи в файл/консоль.
4. Проверка путей `\` в рантайме; при необходимости — автоматическое преобразование при сборке.
5. Один бот FF14x в эмуляторе на данных Binance под WSL.

## Этап 1 — ход работ (2026-09-21)

Выбран путь Б. Сделано:
- `headless/ShimGen` — генератор фальшивого интерфейса. Строит полную Roslyn-модель OsEngine (0 ошибок) с настоящими
  ссылками Windows (`ShimGen/refs.json`) и кодом окон из `obj\Debug\**\*.g.cs`, обходит серверные файлы и роботов
  FF142/FF143/FF142Regime, пишет `OsEngine.Headless/Shim.Generated.cs` (~470 типов, ~1300 членов): пустые реализации,
  коллекции на List (автоматически растут по индексу), `Dispatcher/Control.Invoke` выполняют делегат сразу,
  `CheckAccess` = true, `MessageBox.Show` пишет в stderr, классы вне серверного ядра — `NotSupportedException` в конструкторе.
- Урок: автоматически подменять классы OsEngine опасно — первым подменился `BotFactory` (всегда возвращал null).
  Теперь `shim-allowed.txt` перечисляет, что можно подменять (окна, справка, темы, другие коннекторы), а `shimloop.sh`
  добавляет в серверный набор настоящий код всего остального и повторяет генерацию. Список подменённых классов OsEngine —
  `OsEngine.Headless/shimmed-osengine-types.txt`, проверять после каждого обновления OsEngine.
- `HeadlessProgram.cs` — точка входа: `--root <папка>`, `--mcp-port N`, `--no-mcp`, `--check-bot <класс>`
  (скомпилировать скрипт робота и создать экземпляр). Остановка Ctrl+C/SIGTERM. Сборка называется `OsEngine.dll`.
- Исходники OsEngine не изменены ни в одной строке.

Проверено на Windows (копия `Engine` + `Custom` терминала во временной папке): 30 ботов FF143 H2 и Regime загрузились,
скрипты FF142/FF143/FF142Regime компилируются на лету без правок, BinanceFutures подключился, 30 инструментов подписаны
на свечи Min15, MCP API отвечает (без ключа — 401). Разовая ошибка Binance «Timestamp outside of the recvWindow».

Дальше: запуск под Linux (WSL), проверка путей с `\`, работа ботов на протяжении нескольких свечей, остановка без потерь.

Обновление после нового релиза OsEngine: `refs.json` (команда в `gen.sh`), `bash shimloop.sh`, просмотреть
`shimmed-osengine-types.txt`.
