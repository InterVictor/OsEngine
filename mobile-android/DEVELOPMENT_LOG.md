## 2026-09-28 — второй экран: терминалы VPS

- Добавлены SSHJ 0.40.0 и реальное подключение SSH по паролю. Новый ключ хоста подтверждается по стандартному SHA256-отпечатку SSH и закрепляется локально; изменённый ключ блокирует вход. При включённом автоподключении пароль шифруется ключом Android Keystore.
- Экран терминалов читает через SSH `/proc/stat`, `/proc/meminfo`, `df`, `systemctl` и показывает CPU/RAM/диск VPS, состояния и CPU/RAM экземпляров OsEngine. Данные обновляются каждые 10 секунд. Список служб соответствует настольному `VpsInstances` (`osengine` → `main`, `osengine-имя` → `имя`). На карточке одна команда управления: подтверждаемый `systemctl restart` выбранного сервиса.
- Нажатие на карточку открывает заготовку «Роботы.VPS» с именем выбранного терминала. Данные роботов пока не подключены.
- `assembleDebug` завершился успешно. Проверка на реальном VPS ожидает ручного ввода пароля; учётных данных в репозитории нет. Изменений серверного или настольного кода нет.
- Финальный APK установлен на эмулятор Android 15; второй экран запущен без аварии, сохранён [снимок состояния без SSH](review/second-screen-no-ssh.png). Карточки с живыми службами и реальный перезапуск пока не проверялись: для этого требуется войти с телефона на VPS.

## 2026-09-29 — действия и состояния карточки терминала

- Широкая оранжевая кнопка перезапуска заменена небольшим контурным значком справа от имени терминала. Подтверждение перезапуска сохранено. Для открытия экрана роботов на каждой нажимаемой карточке есть явная подпись «Открыть роботов ›».
- Поле состояния теперь показывает `Connected` зелёным при `systemctl is-active = active`; `Disconnected`, `Failed`, `Starting…`, `Stopping…`, `Reloading…` и `Restarting…` отображаются отдельно. При потере SSH прежний зелёный статус больше не остаётся на карточках, перезапуск блокируется. `Connected` здесь означает доступную через SSH активную службу systemd, не статус биржевого коннектора.
- Список остаётся внутри вертикального `ScrollView`, полоса прокрутки видна постоянно. На телефонном размере прокрутка вручную проверена; сохранены [верх экрана](review/second-screen-compact-restart-phone.png), [нижняя часть после прокрутки](review/second-screen-scroll-phone.png) и [планшетный снимок](review/second-screen-compact-restart-tablet.png). Все снимки сделаны в явно помеченном демонстрационном режиме без VPS.
- Перед компиляцией обнаруженный локальный `OsEngine.exe` (PID 12912) принудительно закрыт согласно правилу пользователя. Android `assembleDebug` завершился успешно; новый APK установлен на эмулятор.

## 2026-09-29 — третий экран: первый рабочий срез

- Вместо заглушки «Роботы.VPS» сделан экран выбранного терминала с постоянной шапкой, статусом SSH и временем последнего успешного обновления. Возврат ведёт к списку терминалов.
- MCP-порт и путь к файлу API-ключа считываются из systemd-службы выбранного терминала. Через существующую SSH-сессию локальный Python 3 на VPS вызывает MCP на `127.0.0.1`; API-ключ остаётся на сервере. MCP-сессия переоткрывается после рестарта сервиса.
- Каждые 5 секунд читаются `bot_get_list` и `server_management_get_list`. На телефоне роботы показаны карточками, на планшете — прокручиваемой таблицей в порядке колонок настольной вкладки. Отображаются имя, тип, первая бумага, открытые/закрытые позиции, Вкл/выкл и Эмулятор.
- Переключатели вызывают `bot_set_state`, затем фактическое состояние перечитывается с VPS. «Добавить бота» использует `wiki_robots_list` и `bot_create`. Вкладка «Серверы» показывает список коннекторов и становится зелёной только при статусе `Connect` хотя бы у одного коннектора.
- На телефоне навигация: Роботы, Позиции, Серверы, Портфель, Ещё; внутри «Ещё» есть Ордера, Прайм лог и служебные пункты. На планшете видны отдельные вкладки. Разделы Позиции, Портфель, Ордера, Прайм лог и действия Чарт, Параметры, Удалить, Журнал пока явно помечены как следующие этапы; серверные команды из этих заглушек не вызываются.
- При потере связи последнее полученное состояние остаётся на экране, показано «Нет связи», команды робота заблокированы. Соединение Android с реальным VPS ещё не проверено; учётных данных в проекте нет. Серверный и настольный код не менялись.
- Перед обеими компиляциями проверен локальный `OsEngine.exe`: в первый раз обнаружен и принудительно закрыт PID 7640, во второй раз процесс уже не работал. `assembleDebug` завершился успешно; APK находится в `app/build/outputs/apk/debug/app-debug.apk`.
