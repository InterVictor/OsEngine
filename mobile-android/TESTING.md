# Проверка OsEngine Mobile

## Текущее состояние

Первый экран и экран терминалов реализованы как нативное Android-приложение. Кнопка «Подключиться» устанавливает SSH-соединение по паролю. После подтверждения нового ключа сервера приложение читает данные VPS и службы OsEngine. При включённом автоподключении пароль хранится в Android Keystore; в остальных случаях пароль не сохраняется.

На компьютере установлены Android Studio `D:\Android\Android Studio` со встроенной Java 25 и SDK `C:\Users\inter\AppData\Local\Android\Sdk`. Доступны Platform 35, Build Tools 36.0.0 и Platform Tools. `assembleDebug` прошёл успешно.

## Как собрать и запустить

1. Использовать установленный SDK Platform 35, Build Tools 36.0.0 и Platform Tools. Для проекта зафиксированы Android Gradle Plugin 9.3.0 и Gradle 9.5.0; используется Java 25 из установленной Studio.
2. Открыть папку `D:\OsEngine-fork\mobile-android` как проект Android Studio; дождаться Gradle Sync.
3. Подключить Android-телефон/планшет с USB debugging или создать виртуальное устройство в Device Manager. Нажать **Run**. Альтернатива: из папки проекта выполнить `gradlew.bat assembleDebug`, затем установить `app\build\outputs\apk\debug\app-debug.apk` через Android Studio или `adb install`.
4. Для первичной визуальной проверки использовать компактный телефон и широкий планшет, обе ориентации. Проверить доступность полей при открытой клавиатуре и прокрутку на небольшом экране.

## Проверки первого экрана

| Действие | Ожидаемый результат |
|---|---|
| Первый запуск | Пустой host, user=`root`, пароль пустой, галочка выключена; видны логотип OsEngine и цвета DarkOrange |
| «Подключиться» с пустым host | Ошибка у поля host, SSH не запускается |
| Заполнить host, оставить user пустым | Ошибка у поля user |
| Заполнить host/user, оставить пароль пустым | Ошибка у поля password |
| Заполнить все поля и нажать кнопку | SSH-соединение; первый ключ сервера требует подтверждения отпечатка; затем открывается список терминалов |
| Включить галочку, подключиться, закрыть и открыть приложение | Приложение подключается автоматически и открывает список терминалов |
| Закрыть и открыть приложение | Host и user восстановлены; пароль снова пустой |
| Телефон/планшет, поворот, открытая клавиатура | Поля, галочка и кнопка доступны без обрезания |

## Проверка после добавления SSH

На устройстве последовательно проверить правильный и неправильный пароль, первый отпечаток сервера, изменённый отпечаток, потерю сети, повторное подключение, автоподключение при новом запуске, выход на экран терминалов и отсутствие открытого пароля в настройках и журналах. На VPS с `main` и `binance` проверить обе карточки, обновление CPU после второй выборки, RAM/диск, подтверждение и фактическое выполнение перезапуска каждого сервиса. Нажатие на карточку должно открыть экран с именем выбранного терминала. Реальный VPS вход требует личного пароля пользователя и здесь пока не проверен.

Для снимка компоновки карточек без подключения к VPS в отладочном эмуляторе доступен внутренний режим `TerminalsActivity` с параметром `preview_terminals=true`. Он подписан «ПРЕДПРОСМОТР · демонстрационные данные», отключает перезапуск и переход к роботам и недоступен в обычной сборке. Его значения не являются результатом измерений VPS.
