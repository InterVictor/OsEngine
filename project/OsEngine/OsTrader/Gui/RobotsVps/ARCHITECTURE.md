# VPS UI architecture

- The main-menu `VPS` button opens `RobotsVpsUi`, the connection and remote-administration window. SSH/MCP settings belong here, along with server deployment, updates, robot-script transfer and remote module restart/compilation controls as those operations are implemented.
- The main-menu `Bot Station VPS` button opens `RobotsVpsWorkspaceUi`, a separate workspace containing only `RobotsVpsLiteClone`: a full visual copy of `RobotUiLite` with its original panels, columns, buttons and checkboxes. It does not instantiate the local engine. Its XAML is independent so VPS-specific changes do not affect `RobotUiLite`.
- Per-computer connection settings are stored in `Engine/RobotsVpsSettings.txt`; the eighth line stores the auto-connect checkbox. When enabled, the main window opens the VPS settings window hidden and establishes the configured SSH tunnel and MCP connection after startup. The window remains alive in the background so its session can serve the workspace.
- The VPS Lite clone reads the shared remote session and polls `bot_get_list` every five seconds. The API response must supply robot number, public/internal name, strategy type, first security, open and closed position counts, and on/emulator flags. The VPS currently returns the list and parameter values, but the latest read-only check found no `is_on` / `emulator_is_on` fields and no `bot_set_state` tool; update the remote MCP server before expecting the state checkboxes to synchronize.
- UI parity milestone (2026-09-23): the VPS Lite clone mirrors the Lite window's localized tab names, window resize/panel splitter behavior, interface lock controls, utility buttons, version strip, shared theme resources, and its own saved layout key (`botStationVpsUi`). VPS-only source hooks remain isolated. Positions, stop-limit/historical positions, active/historical orders, portfolio, prime log and server panes currently display explicit placeholders until corresponding remote data APIs are connected. These placeholders must never initialize or query the local trading engine.
- Remote parameter dialog uses the same `ParamTabPainter` as `StrategyParametersUi`, including the native WinForms grid, editors, label formatting, and type-specific rendering. MCP `bot_get_params` also sends `ParamGuiSettings.ParameterDesigns` so custom foreground, selection, and underline styles can be reproduced. Older VPS MCP builds omit this optional metadata and fall back to the shared default style; deploy the updated server build to receive per-robot custom design metadata.
- `bot_get_params` includes each parameter's `tab_name`, along with the ordered names from `ParamGuiSettings.CustomTabs`. FF143 assigns standard parameters to `Base`, `Base1`, `Base2`, `Regime switch`; `Spectrum` is a custom chart tab and is not part of `BotPanel.Parameters`. The VPS dialog groups standard parameters in first-seen order and adds custom tab placeholders after them. The custom tab's chart content is not serialized yet. An older VPS MCP build without `tab_name`/`custom_tabs` cannot reproduce the correct tabs until its server package is updated.
- Closing the VPS settings window hides it and keeps SSH/MCP connected. `MainWindow_Closing` explicitly disposes the connection while OsEngine exits. The Parameters action opens a VPS dialog using `bot_get_params`, `bot_set_params` and `bot_click_param_button`. It renders rows in a WPF `DataGrid`, matching the working Bots → Parameters view, and groups rows by `tab_name` when supplied by the API. **When adding tabs dynamically, set `TabControlSettings.SelectedIndex` to 0**: otherwise WPF can leave it at -1, so the API data exists but the dialog content stays invisible.
- The robot On/Off and Emulator checkboxes are refreshed from `bot_get_list`; clicks send the requested state to `bot_set_state`, which changes the remote `BotPanel` and returns the server state.
- Build and launch the Windows terminal from `bin/Debug` only. Obsolete `bin/VpsBuild*` folders are removed to avoid launching an older copy by mistake.
- MCP `terminal_open_mode` can open Tester, Tester Lite, Robots, Robots Lite, Data, Optimizer, and Converter windows from a running Windows `MainWindow`. `tester_start` and `optimizer_start` are separate operation commands. The headless Ubuntu process has no GUI window for `terminal_open_mode` to display.
- SSH tunnel (2026-09-26): in-process via SSH.NET (`SshTunnel.cs`), no external ssh.exe. Authenticates with an OpenSSH private key file and/or a password (both secrets and the MCP API key are stored DPAPI-encrypted in `Engine/RobotsVpsSettings.txt`). The server host key is pinned on first use in `Engine/RobotsVpsKnownHosts.txt`; a changed key refuses the connection. The tunnel checks itself every 5 s and reconnects after a drop (5–60 s back-off). `RemoteMcpClient` re-initializes its MCP session on HTTP 404 "Session not found" (server restarted) and raises `Reconnected` when the event stream is back. Provisioning/update/script deployment actions are still future work.
- Server deployment (2026-09-26): the Server section of `RobotsVpsUi` has "Deploy / repair server". `VpsProvisioner` logs in over SSH (`VpsSshCredentials`: registered key / key file / password), uploads by SFTP `VpsServer/osengine-setup.sh` (source `Provisioning/osengine-setup.sh`, copied by the build), the headless build package `VpsServer/osengine-headless-linux-x64.tgz` (from `D:f-researchheadless`, not in git) and a tar.gz of the local `Custom` folder — the package and Custom only when missing on the server — then runs the idempotent script and streams its output to the log. First login with the root password from a computer creates an ed25519 key on the server (`osengine-client-<computer>-<date>` in `~/.ssh/authorized_keys`), verifies it, stores the private key DPAPI-encrypted in the settings and forgets the password; a second computer connects the same way. The MCP API key is read from `/opt/osengine/mcp.key` over SSH.
- Emergency alert forwarding (2026-09-24): `AlertMessageManager.ThrowAlert` raises a local event which the MCP host publishes as `alert.raised` over the existing Streamable HTTP/SSE session. The Robots.VPS connection window receives it and inserts the remote bot/message/time into the same global emergency alert window using `ThrowRemoteAlert` (which deliberately does not re-publish, preventing an event loop). In headless mode, alert generation still publishes over MCP and skips local WPF rendering when no dispatcher text box exists. Watched compare-position mismatches call the same central alert manager after the module's verification delay, in addition to the existing error log. This changes the VPS/server sources `Alerts/AlertMessageManager.cs`, `MCP/McpMaster.cs`, and `Market/Servers/ComparePositionsModule.cs`; deploy the rebuilt server package as well as the Debug client for end-to-end delivery.

## 2026-09-24 — Robots.VPS position table data

`RobotsVpsLiteClone` now feeds the Lite-layout Active positions, Stop Limit and Completed positions grids from read-only remote MCP calls. It creates the original `DataGridFactory` grids and polls at 3-second intervals while SSH/MCP is connected. The server exposes `bot_journal_get_stop_limit_positions` for stop-limit openers across simple tabs and screener child tabs. No order actions are sent from these tables. Server build/deploy and live state are logged in `D:\ff-research\docs\SERVER_SETUP.md`.
